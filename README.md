# whereis

在 Linux 上即时搜索文件名，思路来自 Windows 的 *Everything*。它不遍历目录树，而是只读打开块设备、
直接解码 ext4 文件系统自身的元数据，因此在 50 万条目的文件系统上做一次完整搜索约需 0.1 秒。

**简体中文** · [English](README_en.md)

## 环境要求

* Linux，且根文件系统是块设备上的 **ext4**
* **root** —— 读取块设备需要

## 安装

```sh
cargo build --release     # 产物：target/release/wis
```

包名是 `whereis`，安装出来的命令却叫 `wis`：`/usr/bin/whereis` 已被 util-linux 的同名工具占用，
同名安装会把它遮蔽。这与 ripgrep 的安排一致——包名 `ripgrep`，命令 `rg`。

## 用法

```
wis [选项] <名称>
```

`<名称>` 匹配的是**文件名**而非完整路径，并且按原始字节匹配，所以非 UTF-8 文件名同样可用。
默认是不区分大小写的子串匹配，加 `-r` 后视为正则表达式。

| 选项 | 含义 |
|---|---|
| `-r`, `--regex` | 把 `<名称>` 当作正则表达式 |
| `-n`, `--limit <N>` | 最多输出 N 条，在排序之后应用 |
| `-s`, `--sort <键> [方向]` | 排序键：`path`（默认）、`name`、`ext`、`size`、`mtime`；方向 `asc`（默认）、`desc` |
| `-d`, `--device <路径>` | 扫描指定块设备，而非挂载在 `/` 的文件系统 |
| `-p`, `--path <路径>` | 只搜索该绝对路径（目录）之内的条目；与 `-r` 同用时路径视为正则表达式，匹配到的目录会被递归搜索 |
| `-j`, `--threads <N>` | 并发读取数，默认 16 |
| `--lang <语言>` | 强制输出语言：`zh-Hans`、`zh-Hant`、`en` |
| `-c`, `--clean` | 不输出 stderr 上的统计信息 |
| `-q`, `--quiet` | 输出超过 1000 行时也不询问，直接全部输出 |
| `-h`, `--help` / `-V`, `--version` | 显示帮助 / 显示版本 |

```console
$ sudo wis sshd_config                   # 子串搜索
$ sudo wis -r '^libssl\.so\.[0-9]+$'     # 正则搜索
$ sudo wis -s size desc -n 10 '\.log$'   # 按大小倒序取前 10 个日志
```

结果输出到 stdout（每行一个路径），统计信息输出到 stderr，所以管道接 stdout 是干净的。

一次要输出的结果超过 1000 行时，程序先输出前 1000 行，然后在 stderr 上询问是否继续，
只有输入 `y` 才输出剩余部分。该询问仅在 stdin、stdout、stderr 都是终端时出现，
管道、重定向和脚本中不会被打断。

## 输出语言

支持简体中文、繁体中文和英文，按 `LC_ALL`、`LANGUAGE`、`LC_MESSAGES`、`LANG` 的顺序从环境推断，
其他语言一律回退英文。`--lang` 可无视环境强制指定。

## 已知限制

* 只支持**块设备上的 ext4**，且只搜索**根文件系统**；tmpfs、btrfs、XFS、NFS、FUSE 均不支持。
* 没有索引缓存，每次调用都重新扫描。
* 模式只作用于文件名，不支持 glob。
* 挂载点对扫描是透明的：被挂载点遮蔽的底层内容也会被搜到；`--path` 同样按盘上目录结构解释，不解析符号链接。
